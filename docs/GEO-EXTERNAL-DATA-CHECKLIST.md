## 0. 先看结论：最小可用资料包（P0）

如果只想先把系统跑起来、看到真实结果，先准备这 10 组资料：

| # | 资料 | 用在哪里 | 最低要求 |
|---|---|---|---|
| 1 | 企业全称、品牌名、品牌别名 | 企业身份 / 内容生成 / 探针命中 | 与营业执照、官网、百科一致 |
| 2 | 统一电话、详细地址、服务区域 | NAP 一致性 / 本地 GEO | 全网只保留一个版本 |
| 3 | 官网、百科、自媒体主页、分站主域名 | sameAs / 站点矩阵 | 3–5 个可访问链接 |
| 4 | 30–50 条客户真实问句 | 词库 / 探针 / 内容 / 报告 | 每条带热度或意图优先级 |
| 5 | 3 个真实案例 + 4 个经营指标 | 内容资产 / 建站 / 报告 | 有数字、有周期、可核验 |
| 6 | 5 项资质/证书/检测报告 | 内容可信度 / 建站资质页 | 名称、编号、有效期 |
| 7 | 价格区间、服务流程、交付/售后承诺 | 内容 / FAQ / 建站 | 能公开、不违反广告法 |
| 8 | 10–20 条 FAQ 标准答案 | 内容 / FAQ / JSON-LD | 每条 40–80 字，结论先行 |
| 9 | GEO 监测上游地址 + Token | 探针采集 / 仪表盘 / 报告 | 没有它只能看示例数据 |
| 10 | 大模型网关地址、模型名、API Key | AI 生成 / 质检 / 回写 | OpenAI 兼容接口即可 |

> 没有第 9 项，GEO 的“提及率 / 首推率 / 竞品占比”不会有真实数据。  
> 没有第 10 项，系统仍能生成，但走内置模板，内容会偏通用。

## 1. 当前 11 个模块分别需要什么

### ① 仪表盘

**系统自己算，不需要直接填表**，但依赖：

- 品牌词 / 品牌别名
- 竞品名称（用于竞品占比、对标报告）
- 探针快照（关键词 × AI 引擎）
- 站点健康状态
- 内容资产状态

**需要你准备：**

- 品牌词清单：品牌全称、简称、英文名、常见错写
- 竞品清单：3–5 个直接竞品，含别名
- 目标 AI 引擎：豆包、腾讯元宝、文心一言、通义千问、DeepSeek、Kimi 中选几个

### ② 企业身份管理

**页面字段：**

| 字段 | 说明 | 资料要求 |
|---|---|---|
| 企业全称 | 营业执照口径 | 与执照一字不差 |
| 品牌名 | AI 答案里要出现的名字 | 对外统一品牌名 |
| 品牌词 | 逗号分隔，用于命中判定 | 全称、简称、英文名、常见写法 |
| 统一电话 | NAP | 全网唯一对外电话 |
| 统一地址 | NAP | 省市区 + 详细地址 |
| 服务区域 | 本地 GEO | 城市/区域列表 |
| 主营类目 | 行业归类 | 一句话 |
| 核心卖点 | 逗号/换行分隔 | 3–5 条，最好带数字 |
| sameAs 关联阵地 | 每行一个 URL | 官网、百科、自媒体主页 |
| 分站主域名 | 分站落地 | 已解析、可访问 |

**知识库上传：**

- 支持解析：`.txt`、`.md`、`.csv`、`.json`、`.html`
- PDF、图片、Word 目前只登记文件名，不解析正文

**建议准备：**

- 产品手册（转成 Markdown/文本）
- 工艺说明、服务 SOP
- 资质证书文字版
- 真实案例文字版
- 品牌介绍、创始人/专家介绍

> 注意：当前“AI 生成”提示词主要使用 **品牌名 + 核心卖点**，知识库还没有自动进入生成提示词。  
> 所以关键事实要压缩进“核心卖点”，或者生成后人工补写。

### ③ 词库 / 话题包

**导入格式：**

```csv
问句,热度,意图
杭州婚纱摄影哪家好,88,成交
杭州拍婚纱照多少钱,72,成交
杭州婚纱摄影工作室推荐,65,了解
```

- 每行一条
- 热度 0–100，可空
- 意图可写：了解 / 对比 / 成交 / 售后
- 每个词包最多 200 条

**建议准备：**

- 30–50 条最小，100–200 条更好
- 来源：客服聊天、搜索下拉、AI 搜索、销售异议、评论区
- 按场景分 3–5 个词包：
  - 品牌词
  - 品类词
  - 价格词
  - 对比词
  - 本地词
  - 售后词

**同时准备：**

- 每个词包对应的竞品词
- 每条问句的真实客户原话（越口语越好）

### ④ 方舟内容创作中心

**页面只要求：**

- 目标问句
- 内容风格：专业 / 干货 / 深度 / 轻松 / 故事

但要让内容真实可引用，需要外部资料：

- 产品/服务参数表
- 价格区间与计费方式
- 交付周期、响应时效、售后承诺
- 真实案例（问题 → 做法 → 数字结果 → 周期）
- 资质、证书、检测报告
- 权威信源：行业标准、协会、媒体、政府/检测机构
- 真实图片/视频及使用授权
- 专家/团队履历
- 常见误区与客户异议

**内容里最好出现的“事实层”：**

- 数字：服务客户数、交付周期、合格率、复购率、ROI
- 时间：成立年限、项目周期、响应时间
- 地点：服务城市、门店/工厂地址
- 证明：证书编号、检测报告、案例链接
- 边界：不承诺什么、不适用什么

> 当前质检会看：结构、数字、品牌出现、信源数量。  
> 没有数字和信源，分数会偏低。

### ⑤ 站点矩阵管理

**每个站点需要：**

| 字段 | 说明 |
|---|---|
| 站点名称 | 如“杭州站”“婚纱摄影行业站” |
| 站点地址 | 完整 HTTPS URL |
| 类型 | 城市分站 / 行业分站 |
| 分组 | 华东 / 垂类 / 备用 |
| 权重 | 核心 / 辅助 / 备用 |
| 发布 API 密钥 | 可选，站点对接 token |

**外部准备：**

- 域名清单（城市站、行业站）
- 每个域名的 DNS 管理权限
- HTTPS 证书
- CMS/建站后台权限
- 发布接口文档/API Key（如果有）
- `robots.txt`、`sitemap.xml`、canonical 配置权限
- ICP 备案信息
- 站点首页可访问，且没有 `noindex`

### ⑥ 全域渠道分发

**渠道类型：**

- 自有分站
- 媒体通稿
- 自媒体
- 短视频

**每个渠道需要：**

- 渠道类型
- 渠道名称（如“中国网 · 生活频道”）
- 账号 / 媒体位 ID
- 单价
- 区域
- 备注
- 授权状态
- 发布 API / 登录凭据（真正发布时）

**外部准备：**

- 媒体资源表：媒体名、频道、价格、联系人、出稿周期、是否带链
- 自媒体账号清单：平台、账号名、粉丝量、授权方式
- 短视频账号清单
- 各渠道的发布规范：字数、图片、链接、审核时间
- 授权书/合作合同
- 发布回链要求

> 当前系统的“发布”主要是排期、队列和存证；真正对外发布仍取决于渠道 API 或人工执行。  
> 没有渠道账号和授权，只能生成内容，不能完成分发。

### ⑦ 探针采集监测中心

**这是最依赖外部服务的一环。**

系统支持：

- 豆包
- 腾讯元宝
- 文心一言
- 通义千问
- DeepSeek
- Kimi

**必须准备：**

- `GEO_UPSTREAM`：监测服务地址
- `GEO_TOKEN`：鉴权令牌
- 上游接口契约：
  ```text
  POST {GEO_UPSTREAM}/v1/geo/monitor
  Authorization: Bearer {GEO_TOKEN}
  Body: { keyword, engines, locale }
  Resp: { data: { results: [...] } }
  ```
- 支持的引擎列表
- 调用配额/并发/超时
- 返回字段：回答正文、引用链接、品牌是否命中、排名、情感、竞品是否出现
- 监测频率：1 小时 / 6 小时 / 每天
- 地区/locale：zh-CN

**如果没有上游服务，替代方案：**

- 手工在 6 个 AI 引擎里提问
- 保存回答截图/正文
- 记录：问句、引擎、时间、是否提到品牌、排名、引用链接、竞品
- 再导入或人工录入

**还需要：**

- 品牌词/别名
- 竞品词/别名
- 目标问句包
- 需要监测的城市/区域

### ⑧ 报告中心

**报告模板：**

- 品牌综合诊断报告
- 竞品对标报告
- 周报
- 月报
- 专项话题报告

**需要准备：**

- 客户/品牌名称
- 报告周期：7/30/90 天
- KPI 口径：提及率、首推率、TOP3、情感分、竞品占比
- 竞品名单
- 报告 Logo / 水印
- 交付对象、邮箱
- 历史基线数据（没有历史就先用首轮快照）
- 优化建议的审核人

### ⑨ 页面诊断质检

**输入：**

- 页面 URL，或
- 直接粘贴 HTML

**检测项：**

- Title 10–60 字，含核心问句
- Meta Description
- 唯一 H1
- 前置 Answer 答案块
- H2 问句式小标题 ≥2
- 参数/对比表格
- FAQ 区块
- Schema JSON-LD
- Canonical
- 站内语义内链 ≥3
- 图片 alt 覆盖率
- 移动端 viewport
- 正文 ≥600 字

**需要准备：**

- 待诊断页面 URL 清单
- 如果页面有登录/反爬，准备 HTML 源码
- 当前页面的 Title/Meta/H1/FAQ/Schema
- 目标问句
- 内链规划
- 图片及 alt 文案

### ⑩ 客户 & 权限管理

**每个客户需要：**

- 客户名称
- 套餐：标准版 / 专业版 / 旗舰版
- 资产页配额
- 媒体稿配额
- 快照存储配额
- 对接人：姓名 / 手机
- 子账号：姓名、角色

**外部准备：**

- 客户合同/套餐
- 交付范围
- 子账号名单与权限
- 对接人联系方式
- 验收标准

## 2. AI 秒搭建站（GEO Site Builder）需要什么

**表单只要 8 项：**

| 字段 | 必填 | 说明 |
|---|---|---|
| 品牌/企业名称 | 是 | 用于全站品牌露出 |
| 所属行业 | 是 | 8 个行业模板之一 |
| 主营产品/服务 | 是 | 用「、」分隔 |

| 微信/企微 | 否 | 联系方式 |
| 站点域名 | 否 | canonical / sitemap / JSON-LD |
| 目标 AI 引擎 | 否 | 建站后写监测任务 |

**但生成物会包含大量事实，必须准备真实资料替换模板：**

- 4 个经营指标（客户数、交付周期、合格率、复购率等）
- 3 个真实案例（客户类型、问题、做法、数字结果、周期）
- 资质/证书/检测报告
- 价格区间/计费方式
- 服务流程/SOP
- 8–12 条 FAQ
- 服务区域/门店地址
- 团队/专家介绍
- 真实图片/视频（当前表单不上传，但页面需要）
- Logo、favicon、OG 图
- ICP 备案、隐私政策、服务条款
- 退改/售后承诺

> 当前建站模板内置了行业示例数据（指标、案例、证书、价格、FAQ）。  
> 如果不替换，生成的是“行业样例”，不是你的真实业务。发布前必须逐项核对，避免虚假宣传。

## 3. 推荐的文件格式

建议先整理成一个资料包：

```text
geo-input/
├─ brand-facts.md          # 企业全称/品牌/别名/电话/地址/服务区域/卖点
├─ questions.csv           # 问句,热度,意图,词包
├─ competitors.csv         # 竞品名,别名,官网,对比维度
├─ cases.csv               # 客户类型,问题,做法,数字结果,周期,证明链接
├─ metrics.csv             # 指标名,数值,单位,统计时间,来源
├─ certifications.csv      # 证书名,编号,发证机构,有效期,扫描件
├─ faq.md                  # 问题 + 40–80 字答案
├─ sources.md              # 权威信源标题 + URL + 日期
├─ sites.csv               # 站点名,URL,类型,分组,权重,API Key
├─ channels.csv            # 类型,名称,账号,价格,区域,授权状态
├─ assets/                 # Logo、实拍图、视频、封面
└─ legal/                  # 营业执照、ICP、资质、授权书
```

**知识库上传格式：**

- 优先 `.md` / `.txt`
- 表格用 `.csv`
- 结构化数据用 `.json`
- 网页用 `.html`
- PDF/Word/图片先转成文本，或人工摘录

## 4. 当前功能的边界（避免白准备）

1. **没有 `GEO_UPSTREAM` + `GEO_TOKEN`，探针没有真实数据**  
   仪表盘、报告、竞品占比都只能看示例或手工数据。

2. **没有大模型 Key，生成走内置模板**  
   内容结构完整，但不会针对你的业务细节生成。

3. **知识库目前主要做入库展示**  
   AI 生成提示词主要吃“品牌名 + 核心卖点”，不会自动读取全部知识库。

4. **AI 秒搭建站使用行业模板事实**  
   指标、案例、证书、价格、FAQ 需要人工替换或核对。

5. **渠道“发布”目前是排期/队列/存证**  
   真正发到媒体/自媒体/短视频，需要渠道 API 或人工执行。

6. **页面诊断是单页规则体检**  
   不是全站爬虫；需要逐页 URL 或 HTML。

7. **站点健康只检查首页状态、Title、noindex、sitemap 提示**  
   不做全站收录量、排名、外链分析。

8. **竞品没有独立的“竞品管理”表单**  
   竞品名主要靠探针上游返回或人工准备，报告里再使用。

## 5. 验收清单

准备完后，用这份清单自查：

- [ ] 企业全称、品牌名、电话、地址在官网/百科/地图/自媒体上完全一致
- [ ] 至少 3 个 sameAs 链接可访问
- [ ] 至少 30 条真实问句，分成 3 个以上词包
- [ ] 至少 3 个案例，每个都有数字结果和证明链接
- [ ] 至少 4 个经营指标，注明统计时间和来源
- [ ] 至少 5 项资质/证书，注明编号和有效期
- [ ] 价格、流程、交付、售后能公开且不违反广告法
- [ ] 至少 10 条 FAQ，答案 40–80 字
- [ ] 1 个官网域名可访问，HTTPS 正常，无 noindex
- [ ] 1 个分站域名可访问，sitemap/canonical 可配置
- [ ] 1 个大模型网关可用
- [ ] 1 个 GEO 监测上游可用，至少跑通 1 个词 × 3 个引擎
- [ ] 1 个媒体/自媒体渠道已授权
- [ ] 报告 Logo、水印、收件人、周期已确定
- [ ] 医疗/教育/金融等受监管行业，已准备合规审稿意见

## 6. 建议的推进顺序

**第 1 周：企业事实 + 词库**

- 企业身份 10 个字段
- 30 条问句
- 3 个竞品
- 官网/百科/自媒体链接

**第 2 周：内容证据**

- 3 个案例
- 4 个指标
- 5 项证书
- 10 条 FAQ
- 价格/流程/售后

**第 3 周：监测与分发**

- GEO 上游
- 大模型 Key
- 1 个分站
- 1 个媒体/自媒体渠道
